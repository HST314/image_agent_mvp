# Image Agent 用户与开发者指南

## 创建第一个任务

1. 在主系统工作台选择“新建任务”。
2. 用自然语言说明创作目标、使用场景、目标人群和交付要求。
3. 上传品牌手册、参考图或文字资料。
4. 与 Master 补齐必要信息并确认计划。
5. 审阅 Image Agent 的 TaskCard 后启动任务。

任务启动后，主系统会固定该任务的运行快照并创建受管 Image Agent 实例。普通用户不需要选择 Provider、模型、接口地址或运行参数。

## 完成图片创作

Image Agent 会依次经历以下阶段：

1. 必要澄清：回答确实影响交付的问题。
2. 任务书确认：核对目标、已知事实、未知项和交付规格。
3. 候选生成：生成五个差异化方向。
4. 主图选择：人工选择一个方向进入质检。
5. 质检与返工：查看视觉检查结论，按需要继续修改。
6. 最终确认：确认交付后冻结图片与设计说明。

每个成功节点都会形成 Checkpoint。浏览器关闭、进程重启或供应商调用失败后，已有成功结果仍会保留；继续任务不会重复已经确认的付费步骤。

## 分支与恢复

- “重试”从最后成功点重跑失败状态，并创建新分支。
- “从此处分支”从历史 Checkpoint 派生新方向，不修改原分支。
- “工程健康检查”只读检查索引、Checkpoint 和资产引用；仅在结果可唯一确定时才允许修复。
- 对结果未知且可能计费的调用，必须由人工明确选择重试或放弃。

## 受管运行边界

主系统是运行配置的唯一事实源。Image Agent 仓库不保存可人工维护的生产模型路由或运行策略；每个实例只读取主系统按任务快照生成的只读文件。Provider 秘密只通过受控子进程环境注入，不写入任务、日志、Prompt、Checkpoint 或交付文件。

受管 Web 创建接口只接受主系统 Adapter 的本机请求，并校验实例身份与请求密钥。普通页面和维护 CLI 均不能覆盖任务快照、选择私有模型配置或启用测试 Provider。

## 开发者测试

```bash
python3 -m pytest -q
node --test frontend_tests/js/*.test.mjs
```

测试通过 `tests/fixtures` 与显式 fake client 注册覆盖状态机、模型路由、浏览器交互、恢复、并发和安全边界。测试夹具不属于安装包的正式运行配置，正式入口也不会自动读取它们。

新增能力时应同时补充：

- 领域契约与错误语义；
- 成功、失败、恢复和幂等测试；
- 受管 Adapter 契约回归；
- 不调用真实付费模型的发布门禁；
- 与主系统任务快照和用户文档一致的说明。
